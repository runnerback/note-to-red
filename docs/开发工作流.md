## 2. 构建

```bash
# note-to-red（tsc 类型检查 + esbuild，产出 main.js + styles.css）
cd ~/Documents/MediaCrawlerPro/obsidian-plugin/note-to-red
npm install                 # 首次
npm run build

# wechat-converter（先 generate:runtime 生成内嵌依赖，再 esbuild 产出 main.js）
cd ~/Documents/MediaCrawlerPro/obsidian-plugin/obsidian-wechat-converter
npm install --legacy-peer-deps   # 首次；因 eslint 相关 devDep 有 peer 冲突，必须加此参数
npm run build
```

要点：
- **wechat-converter 改了 `converter.js` / `themes/apple-theme.js` 等被内嵌的源，必须重新 `npm run build`**（build 会先跑 `generate:embedded` 重新生成 `services/generated-embedded-deps.js`）。只改不重生成 → 运行时用的还是旧快照。
- `wechat-converter` 的 `styles.css`、`manifest.json` 是**源文件**（不是构建产物），手改即可。
- `note-to-red` 的 `styles.css` 是 esbuild 从 `src/styles/` **生成**的，别手改根目录 styles.css，改 `src/styles/` 下的源。

## 3. 部署到 Vault

部署脚本在 `note-to-red/docs/deploy-to-vault.sh`（路径相对自身解析，可移动；vault 路径可用 `OBSIDIAN_VAULT` 环境变量覆盖）：

```bash
cd ~/Documents/MediaCrawlerPro/obsidian-plugin/note-to-red/docs
./deploy-to-vault.sh            # 两个都部署
./deploy-to-vault.sh note-to-red
./deploy-to-vault.sh wechat
# 若 vault 换了位置：
OBSIDIAN_VAULT="/path/to/vault" ./deploy-to-vault.sh all
```

脚本只复制 `manifest.json` / `main.js` / `styles.css`，**不动 data.json**。

## 4. 日常开发循环（方式 A：直接在真实 Vault 里开发）

1. 安装 **Hot Reload** 插件（一次性，见第 6 节）。
2. 一个终端跑监听构建：
   ```bash
   cd ~/Documents/MediaCrawlerPro/obsidian-plugin/note-to-red && npm run dev            # esbuild watch
   # 或
   cd ~/Documents/MediaCrawlerPro/obsidian-plugin/obsidian-wechat-converter && npm run dev
   ```
3. 改代码 → watch 自动重编译仓库里的 `main.js` → 跑一次部署脚本复制进 Vault → `.hotreload` 让 Hot Reload 自动重载：
   ```bash
   ~/Documents/MediaCrawlerPro/obsidian-plugin/note-to-red/docs/deploy-to-vault.sh note-to-red
   ```
4. 第一次换版本或改了 manifest 版本号时，做一次完整重载：`Cmd+P` → **Reload app without saving**。

> 缺点：`wechat-converter` 的 `main.js` 有 4.2MB，每次部署都会被 SynologyDrive 同步一遍（同步噪音）；多设备同时开 Obsidian 容易产生 `_Conflict`。建议开发时只在这台 Mac 上开 Obsidian。

### 方式 B：独立本地开发库（可选，当前未启用）

> 本工作流当前采用**方式 A**。方式 B 只是“将来嫌 SynologyDrive 同步噪音大”时的可选方案，**现在没有搭建**。

思路：在一个**不在 SynologyDrive 里**的本地库（如 `~/ObsidianDev`）里，用整目录软链接把两个仓库接进去 + 装 Hot Reload；`npm run dev` watch 后改代码自动重载、无同步噪音；稳定后再用 `deploy-to-vault.sh` 复制回真实库。macOS 上 Hot Reload 专门监听“软链接形式 + 含 .git/.hotreload”的插件目录，两仓库都有 `.git`，因此这种方式无需 deploy 即可热重载。

## 6. 安装 Hot Reload 插件（一次性）

```bash
cd "<Vault>/.obsidian/plugins"
git clone https://github.com/pjeby/hot-reload.git
# 或不装 git：从 https://github.com/pjeby/hot-reload 下载 manifest.json + main.js 放进 hot-reload/ 目录
```
然后在 Obsidian 第三方插件列表启用 “Hot Reload”。之后凡是插件目录里有 `.hotreload` 或 `.git` 的插件，`main.js`/`styles.css` 变化时会被自动禁用再启用。

## 7. 回滚到官方版本

已不再保留本地备份。要回官方版，最稳的是**从 Obsidian 社区插件商店重装**：设置 → 第三方插件 → 浏览 → 搜索 “Note to RED” / “Wechat Converter” → 安装覆盖。你的 `data.json`（设置/账号）一直没动，重装后设置仍在。

## 8. 常见坑

- 换版本后没生效 → 没做「Reload app without saving」/ 没装 Hot Reload / 忘了 deploy。
- `wechat-converter` 改核心渲染没重跑 build → 用的是旧的 `generated-embedded-deps.js`。
- 多设备同步冲突 → 开发期只在一台机器开 Obsidian；或改用方式 B 的本地库。
- `npm install`（wechat）报 peer 冲突 → 加 `--legacy-peer-deps`。
- **别提交密钥**：`data.json` 含 appSecret，两仓库的 `.gitignore` 已忽略 `data.json`；不要把它复制进仓库工作树，也不要 `git add -f`。
- 想额外备份 `data.json` → 复制到**仓库之外**的目录（如 `~/obsidian-plugin-backups/`），不要放进 git 仓库。
